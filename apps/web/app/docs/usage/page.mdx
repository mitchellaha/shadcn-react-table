# Usage

The data table has one core idea: **options in, instance out.**

```tsx
const table = useDataTable(options) // enriched TanStack instance
return <DataTable table={table} />  // renders it
```

## The hook

`useDataTable(options)` wraps TanStack's `useTable`. It:

- registers every TanStack feature and row model the table needs (core, sorted, filtered, faceted, grouped, expanded, paginated), toggled by the feature flags;
- injects display columns when needed (selection, row numbers, drag handle, expand, row actions);
- merges localization and icons (built-in defaults → [`DataTableConfigProvider`](/docs/guides/custom-icons) → per-call options);
- attaches all presentation state + feature flags to the instance as **`table.tableInstance`**.

Because it extends TanStack's `TableOptions`, **anything TanStack accepts passes through**: controlled `state`, `on*Change` handlers, `manual*` server-side flags, `getRowId`, `getSubRows`, `initialState`, and so on.

```tsx
const table = useDataTable({
  data,
  columns,
  getRowId: (row) => row.id,
  // data-table options
  enableGrouping: true,
  // standard TanStack options, passed straight through
  state: { sorting },
  onSortingChange: setSorting,
  manualPagination: true,
  rowCount: total,
})
```

## The component

`<DataTable table={table} />` reads `table.tableInstance` and renders the full layout: top toolbar → alert banner → drop-to-group zone → bordered scroll surface (sticky header, optional filter row, body, optional sticky footer) → pagination.

It takes a few presentational props — see [DataTable props](/docs/api/data-table-props). The most common is `surfaceClassName`, used to bound the scroll surface for sticky headers or virtualization:

```tsx
<DataTable table={table} surfaceClassName="max-h-[600px]" />
```

## The instance: `table.tableInstance`

Sub-components read configuration and UI state from `table.tableInstance` rather than via props. You can use it too — for toolbar actions, custom layouts, or programmatic control:

```tsx
renderToolbarActions: ({ table }) => (
  <Button onClick={() => table.tableInstance.beginCreate()}>New row</Button>
)
```

It also exposes density (`density`, `setDensity`), fullscreen, filter visibility, editing state (`beginRowEdit`, `cancelEdit`, …), and every feature flag. See the full [Table instance](/docs/api/table-instance) reference.

## Columns

Columns are standard TanStack [column defs](https://tanstack.com/table/latest/docs/guide/column-defs), typed with the exported `DataTableColumnDef`. The table reads extra per-column configuration from **`columnDef.meta`** — filter variant, alignment, edit variant, aggregation labels, click-to-copy, and more. See [Column options](/docs/api/column-options).

```tsx
const columns: DataTableColumnDef<Person>[] = [
  {
    accessorKey: "status",
    header: "Status",
    meta: { variant: "multi-select", options: STATUS_OPTIONS },
  },
  {
    accessorKey: "salary",
    header: "Salary",
    aggregationFn: "sum",
    meta: { align: "right", variant: "range-slider", editVariant: "number" },
  },
]
```

## The `table` inside your own renderers

`useDataTable` returns a React wrapper around the core TanStack table, and only that wrapper carries `state` and `tableInstance`. The `table` handed to your own `cell` / `header` / `footer` renderer is the **core** table, so it has neither. Call `resolveDataTable(table)` to get the enriched instance back — package-owned render props such as `renderRowActions` already receive the resolved instance.

```tsx
import { resolveDataTable } from "@/components/ui/data-table"

{
  accessorKey: "status",
  cell: ({ table, row }) => {
    const dt = resolveDataTable(table)
    return dt.state.grouping.length > 0 || dt.tableInstance.density === "compact"
      ? <Compact value={row.original.status} />
      : <Full value={row.original.status} />
  },
}
```

## App-wide defaults

Wrap a subtree in `DataTableConfigProvider` to set default `icons` and `localization` for every table inside it, without editing each call site:

```tsx
import { DataTableConfigProvider } from "@/components/ui/data-table"

<DataTableConfigProvider localization={spanish} icons={lucideIcons}>
  <App />
</DataTableConfigProvider>
```

Precedence is: built-in defaults → provider → per-call `useDataTable({ localization, icons })`.
